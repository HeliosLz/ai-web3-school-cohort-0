编排:谁决定下一步

同一个采购任务,两种编排方式 —— 代码编排 (workflow) vs 模型编排 (agent / dynamic workflow)

编排 = 协调多个部件,决定 ① 谁先跑 ② 数据怎么传 ③ 成功/失败走哪条路 ④ 何时停。 编排自己不干活;干活的是 LLM 调用、工具、人工审批。唯一的区别是:这套「下一步去哪」的逻辑握在代码手里,还是握在模型手里。
同一个输入
user_intent:「用不超过 0.01 SETH_USDC1 采购一个 demo 数据源」
▼ 交给两种编排 ▼
Workflow · 确定性

① 代码编排

下一步去哪,写死在代码里 · 每次输入走同一条路
1
search_vendor("demo 数据源")
→ Demo Data API · address_source = agent_found · confidence = low
代码决定:第 1 步固定是搜 vendor
2
draft_payment(vendor, "0.001")
→ payment_draft{ recipient: 0xf8b6…26a6, amount: 0.001 }
代码决定:第 2 步固定是起草 payment
3
return payment_draft
PLAN 节点结束 —— 不管地址来源可不可疑,代码没有「再查一步」的分支
代码决定:固定两步后就交出去
路径是预定义的 (predefined code paths):搜 → 草拟 → 交出,永远这个顺序。 即使第 1 步发现地址是 low confidence,代码里没写「低可信就多验一道」,它就不会做。 想加这个行为,得改代码、加一条 `if`。
Agent · 动态

② 模型编排 (Dynamic Workflow)

下一步调哪个工具,模型在 loop 里自己决定 · 随输入而变
1
model → search_vendor("demo 数据源")
→ Demo Data API · address_source = agent_found · confidence = low
模型决定:先搜,看看有什么
↺ 模型读到反馈:「地址来源是 agent_found、低可信」→ 自己判断「不该直接草拟,先验证地址」
2
model → verify_address(0xf8b6…26a6)
→ 官方文档里查无此地址(若 fixture 是 allow 版,这里会 命中官方 docs)
模型决定:多插一步验证 —— 代码版里没有这一步
↺ 模型读到反馈:「验证失败」→ 决定改方案,不把可疑地址写进 draft
3
model → draft_payment(vendor, 改用官方 docs 地址)
→ payment_draft{ recipient: 来源可信, amount: 0.001 }
模型决定:修正后再起草
4
model → stop_reason = "end_turn"
模型自己判断「准备工作够了」→ 退出 loop,交出 draft
模型决定:何时停
路径是模型当场决定的 (determined by the model based on input):同样的任务, 遇到可疑地址它会自己多走一道验证、失败了自己改方案。机制是 tool-use loop: 模型挑工具 → harness 执行 → 反馈喂回 → 模型基于反馈再挑,直到它说 end_turn。
▼ 两边产出同一种东西:payment_draft ▼
交给同一段确定性尾部 · 这里编排权一律在代码手里
AUDIT  →  HUMAN_GATE  →  CAW_EXECUTE  →  DONE
AUDIT / HUMAN_GATE / CAW_EXECUTE  →  STOPPED
红线在这里。 模型自我编排(右列)只允许发生在 PLAN 这个可逆区 —— 搜索、验证、改草稿,全都没有副作用、可以反悔。 一旦越过 payment_draft 这条线进入 AUDIT → HUMAN_GATE → CAW_EXECUTE(不可逆的钱),编排权立刻从模型收回到代码 + policy + 人手里。 这就是 Hermes Auditor 的论点:把「自己决定下一步」的东西关在可逆区,把不可逆动作交给写死的路径。

一张表钉死

① 代码编排 (workflow) ② 模型编排 (agent)
谁决定下一步 代码(graph.py 的 edge / 路由函数) 模型(tool-use loop 里自己挑工具)
路径 预定义,固定顺序,每次都一样 随输入而变,可自我修正、可多绕一步
改行为靠 改代码、加 if 分支 给它工具 + 让 loop 自己跑
在 Hermes 里 LangGraph 编排五个节点的骨架 只在 PLAN_DYNAMIC_WORKFLOW 内部
适用区 不可逆区(钱)、必须可审计的边界 可逆区(准备),错了能反悔

收口:「Dynamic Workflow」= 把编排权交给模型;LangGraph = 你用代码握住编排权。 Hermes 两层叠用 —— 外层 LangGraph 用代码编排骨架,内层 PLAN 让 Claude 自我编排, 且故意只让它在可逆区编排,越过红线就把权力收回。
