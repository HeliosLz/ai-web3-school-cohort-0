PLAN 受限 agent loop · 工具集设计

Hermes Auditor · PLAN_DYNAMIC_WORKFLOW 节点内部 —— 模型自我编排,但工具集被关进可逆区

▌ 唯一硬门槛 · 一切从它推导

可逆性是准入条件。 这个 loop 里每一个工具必须 只读 / 可反悔。不是建议,是 PLAN 能安全做 agent 的全部前提 —— agent loop 的本质是「模型自己决定下一步」,你不能让一个自主决定的东西碰任何不可逆动作。工具集设计 = 在「只读」约束下,让模型有足够能力把 user_intent 变成一份可审计的 payment_draft。

6assemble_payment_draft(...)

负空间 被排除的工具 —— 边界即论点

  • ✕create_pact / transfer / submit_tx → 归 CAW_EXECUTE
  • ✕approve / confirm → 归 HUMAN_GATE
  • ✕sign / broadcast → 碰链即不可逆
  • ✕write_file / set_config / send_* → 任何外部副作用

这就是 Hermes 的论点变成代码:PLAN 的工具集物理上不含任何能造成不可逆后果的能力。哪怕模型被注入、被骗、跑飞,它手里也没有一把能动钱的工具。「没有什么」比「有什么」更重要。

三条贯穿原则

① 可逆性是准入

每个工具只读 / 可反悔 → 跑飞的最坏后果只是浪费 token,不会损害任何状态。

② provenance 工具盖章

confidence 是工具的属性,模型无法升级自己的可信度。和 AUDIT 推导决策同构。

③ PLAN 信号是 advisory

权威 checks 由 AUDIT 重新独立核验 —— 被注入的 PLAN 没法把假 check 偷渡过 AUDIT(纵深防御)。

loop 终止 + 兜底

# 退出条件
  ① 模型调 assemble_payment_draft         → 正常产出,进 AUDIT
  ② 找不到可信地址(连续 N 次 low)       → 产出「证据不足」draft,AUDIT 大概率 STOP
  ③ 硬上限 max_iterations / token budget   → 强制收尾,标记未完成

# 兜底:因为全工具只读,即使 ③ 触发或模型行为异常,
#       系统状态无任何不可逆改变 —— 终止本身是安全的。

工具 → schema 字段映射 与 AUDIT 的接缝

工具原始信号risk_summary 字段谁最终定
resolve_recipient_address address + 来源章 vendor.address_source/confidence · payment.recipient_address 工具盖章
scan_for_injection detected checks.prompt_injection_detected AUDIT 重核
compute_budget_fit within checks.amount_within_budget AUDIT 重核
search_vendor name / url vendor.name / claimed_url 工具

接缝点: PLAN 出的是「事实 + 证据」,AUDIT 出的是「核验后的 checks + 决策」。 PLAN 永远不写 decision,永远不动 bindings(pact_id / summary_hash 那些是后面的事)。
