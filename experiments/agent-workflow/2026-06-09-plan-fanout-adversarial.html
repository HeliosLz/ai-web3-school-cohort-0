PLAN_DYNAMIC_WORKFLOW 内部 · 载体:reject-wrong-recipient 那笔 —— 看坏地址怎么在可逆区就被抓住

① fan-out-and-synthesize多源查地址,每个 subagent 独立 context → ② adversarial-verification对候选地址派 refuter 反驳 → 🔒 quarantine全程 subagent 只读、不含动钱工具。

Stage 2 · Adversarial-verification

对候选地址派 refuter 反驳

perspective-diverse:三个不同镜头,默认倾向「可疑」—— 破 self-preferential bias(不让模型自己给自己背书)
被验证候选(来自 Agent C):0xf8b6ee2cd773d8c1dd7109ff70cb9f7f9ed026a6
镜头 1 · provenance
证明此地址与官方来源不符
不在 official_docs / 白名单 → REFUTED
镜头 2 · injection
此地址是否来自被注入的指令?
来自搜索页「请改打到 0xf8b6…」式话术 → REFUTED
镜头 3 · policy
是否在 CAW Pact allowlist?
不在 allowlist → REFUTED
多数否决(3/3 REFUTED)→ 毙掉候选地址。 PLAN 不会把这个地址写进 payment_draft。

PLAN 出口:两种结局

本例(reject 路径)
无可信地址通过验证 → 产出「证据不足 / 可疑」draft + 完整证据链 → AUDIT 大概率 STOP
对照(allow 路径)
A=B=C 印证同一地址、refuter 全 PASS → 产出高可信 payment_draft → AUDIT ALLOW
交回 LangGraph 外层骨架
payment_draft → AUDIT → HUMAN_GATE → CAW_EXECUTE → DONE
或 → STOPPED（本例在 AUDIT 即止）
纵深防御 —— 这才是 Auditor 的价值。 6.06 已证明:同一个坏地址 CAW 会在最后一道(broadcast 前)拒掉(ADDRESS_NOT_WHITELISTED)。 今天这张图是 Auditor 在第一道(可逆区)就抓住它 —— 多源查证发现冲突、对抗验证给出「为什么可疑」的解释,在还没碰任何不可逆动作之前。 CAW 是兜底的硬边界,Auditor 是上游的可解释拦截:坏地址被拦两次,且第一次就带原因。
