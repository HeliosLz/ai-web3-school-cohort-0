## 我学到了什么（自己复述一遍）

- **三层记忆**：短期 = context window；长期 = 跨 session 持久化（带索引、可检索）；用户模型 = Honcho dialectic modeling。关键不是"存"，而是**带 FTS5 + LLM 摘要的检索**。
- **Skills = Agent 自己写给自己看的 SOP**：一个 `SKILL.md` 描述"这是什么 / 怎么做 / 踩过哪些坑 / 何时用"。第二次遇到任务直接调技能，做完后还会自问"有没有更好的写法"，然后改技能。
- **设计哲学一句话**：不要每次从零开始，把经验变成资产。

## 留给自己的作业（来自打卡原文）

> 如果 Hermes Agent 帮你完成了一个"自动整理邮件"的任务，它在背后经历了哪几个步骤？它下次再做类似任务时，会有什么不同？

我现在的答案草稿（待回填）：

- 第一次：用 LLM 决定调用什么工具 → 调用邮件 API → 返回结果 → 判断"这个流程有用 → 生成 SKILL.md 描述步骤、入参、典型陷阱"
- 第二次：检索到 skill → 直接按 skill 步骤执行 → 完成后自问"这次有没有更好的写法" → 增量更新 skill
- 关键差异：从"每次让 LLM 重新推理工具序列"变成"读已有 skill + 必要时小幅改写"，token 成本和延迟都下降。
