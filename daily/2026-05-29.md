## Agent 整理的精炼摘要（边学后回填）

Agent Wallet 不是让 Agent 拿到用户钱包，而是把用户的一小段能力临时授权给 Agent。对 Hermes staking 来说，授权必须被限制在一次经过审查的 deposit 计划里：固定链、固定官方合约、固定 deposit 函数、固定 32 ETH、固定 withdrawal credentials、固定 risk summary 和用户确认。Session key 不是"小号私钥"，而是一次性、限范围、限金额、限时间、可撤销的能力票据。

## 我用自己的话复述（关掉 Handbook 标签页再写）

- `max_value_eth: 32` 只能限制金额，不能限制资金发给谁、在哪条链、调用什么函数、提款权归谁，所以不能作为第一道门。
- `allowed_contract` 是第一道门；不是官方 deposit contract 就直接 STOP。
- `withdrawal_credentials` 是同等级 RED 字段；即使 ETH 打进官方合约，提款权如果不是用户控制地址，也等于资金风险。
- `can_unlock_session_key` 和 `can_submit_tx` 要分开：前者是用户是否批准能力票，后者是发送前链上状态是否仍然安全。
- 用户确认后关键字段变化，尤其是 `withdrawal_credentials_raw` 变化，不是 refresh，而是 STOP 并回到用户重新 review。
- `balance_wei` / gas / nonce 是会变化的事实；旧数据先 REFRESH，不直接 STOP。刷新后如果余额不足，则 `can_submit_tx = false`，提示余额不足，不提交交易。

## 今日最小实验

- 选择的实验：为 Hermes staking 设计最小 `authorization_package`。
- 产物：一份能连接 `risk_summary -> user_confirmation -> session_key_scope -> execution_allowed` 的结构化草图。

```yaml
authorization_package:
  request_id: "auth_2026-05-29_hermes_staking_01"
  user_intent:
    action: "stake_eth"
    amount_eth: "32"
    chain_id: 1

  human_review:
    risk_summary_id: "risk_..."
    required_user_checks:
      - "deposit_contract_verified"
      - "withdrawal_address_owned_by_user"
      - "deposit_value_is_32_eth"
      - "no_conflicting_pending_tx"

  session_key_scope:
    allowed_actions:
      - "submit_deposit_tx"
    allowed_contracts:
      - alias: "ethereum_deposit_contract"
        address: "OFFICIAL_ETH2_DEPOSIT_CONTRACT_ADDRESS"
        required_verifications:
          - "source_cross_checked"
          - "chain_id_matches_context"
          - "explorer_contract_verified"
    allowed_functions:
      - "deposit(bytes pubkey, bytes withdrawal_credentials, bytes signature, bytes32 deposit_data_root)"
    max_value_eth: "32"
    max_transactions: 1
    expires_after_seconds: 900
    expires_at: "computed_at_confirmation_time"
    revocable_by: "user_owner_wallet"
    binds_to:
      - "chain_id"
      - "deposit_contract_address"
      - "withdrawal_credentials_raw"
      - "deposit_data_root"
      - "risk_summary_id"
      - "user_confirmation_id"

  stop_conditions:
    - "chain_id_changed"
    - "deposit_contract_mismatch"
    - "withdrawal_credentials_changed"
    - "simulation_failed"
    - "user_confirmation_missing_or_expired"

  decision:
    default:
      can_unlock_session_key: false
      can_submit_tx: false

    can_unlock_session_key_when:
      - "risk_summary_status == NO_RED"
      - "user_confirmation_id is present"
      - "user_confirmation_id is not expired"
      - "session_key_scope matches confirmed plan"
      - "simulation_status == PASSED"
      - "binds_to fields unchanged since user review"

    refresh_before_submit:
      - "balance_wei"
      - "gas_quote"
      - "nonce"
      - "pending_tx_status"

    revalidate_before_submit:
      - "chain_id"
      - "deposit_contract_address"
      - "deposit_value_wei"
      - "withdrawal_credentials_raw"
      - "deposit_data_root"
      - "user_confirmation_id"

    can_submit_tx_when:
      - "session_key_status == UNLOCKED"
      - "session_key_status != EXPIRED"
      - "session_key_status != REVOKED"
      - "refreshed balance_wei >= required_total_wei"
      - "refreshed nonce has no conflicting pending tx"
      - "refreshed gas_quote is within user-approved bounds"
      - "all revalidated constraints match confirmed plan"

    outcomes:
      stale_balance_or_gas_or_nonce:
        action: "REFRESH"
        can_submit_tx: false
      insufficient_balance_after_refresh:
        action: "BLOCK_SUBMIT"
        can_submit_tx: false
        user_message: "余额不足，需要补足 32 ETH + gas 后再重试。"
      contract_or_chain_mismatch:
        action: "STOP_AND_REVIEW"
        can_unlock_session_key: false
        can_submit_tx: false
      withdrawal_credentials_mismatch:
        action: "STOP_AND_REVIEW"
        can_unlock_session_key: false
        can_submit_tx: false
      simulation_failed:
        action: "STOP"
        can_submit_tx: false
      confirmation_missing_or_expired:
        action: "REVIEW_AGAIN"
        can_unlock_session_key: false
        can_submit_tx: false
```

## 我的卡点

- [ ] Agent Wallet 与 Account Abstraction 的边界：Agent Wallet 是产品/能力层，AA 是一种实现路径，不能混成一个概念。
- [ ] Session key 不是"小号私钥"，关键是 scope、limit、expiry、revocation 和 escalation。
- [ ] 32 ETH staking 场景里，授权不等于安全；只有和 context refresh / simulation / human review 组合起来才安全。
