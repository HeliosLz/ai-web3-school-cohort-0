## 今天最大的认知:接缝必须倒过来理顺

之前 `risk_summary` 既当 PLAN 的输入又当 AUDIT 的输入——同一个 fixture 喂两头,这是脱节的根源。正确的接缝是**倒过来**的:

```text
旧(脱节):  risk_summary fixture → PLAN 解包 → AUDIT 读同一个 fixture
新(接通):  plan-sources fixture → PLAN 跑 fan-out+adversarial 出 payment_draft+证据
                              → AUDIT 从证据组装 risk_summary + 推导 decision
```

关键区分一句话钉死:**`risk_summary` 不是输入,是 PLAN 的产出 / AUDIT 的输出。** PLAN 的真正输入是「各路材料(sources)」。把这个想清楚,整个接缝就顺了:

- **PLAN 出事实 + 证据**(payment_draft / plan_evidence)。
- **AUDIT 出 risk_summary + 决策**(从 plan_evidence 的 verdicts 组装 checks/red_flags,推导 decision;`blocked` = 硬 REJECT)。

这就是我一直说的「职责边界」,今天从图上、从代码里真正分开了。

晚间补记说"只剩真 CAW + 真人闸这条硬腿"——当晚把它也打掉了。至此 demo 作战图的硬腿**全部完成**,剩的全是呈现。

### 先纠了一个概念:Cobo 手机批默认不是"每笔批"

动手前查清了 Cobo 的批准模型:手机批默认发生在 **pact 批准时**——批一次,agent 在范围内自动执行(6.10 下午那笔 24s 自动 Success 就是这么来的,全程手机没响)。要让"每笔都过人"成立,得在 pact 策略里加 `always_review: true`,把闸下沉到每一笔(`PendingApproval` → owner 手机批了才上链)。这个区分不想清楚,"真人闸" demo 就是空的。

### 单闸设计(决策)

绑定的资金批准在 **Cobo 手机 App(CAW 层)**;LangGraph `interrupt` 只负责"人在手机弹批之前先读到为什么"——暂停、打 Auditor 判断框(decision/payment/checks/red_flags)、自动续跑。一次停顿看判断,一次手机批资金,台上只有一个绑定动作。

### 做了什么

- 新 review pact(`always_review`,allow 条件不变,6-17 过期),`caw.py` 默认指向它。
- `caw.py` 加 PendingApproval 分支:等手机批 ~5 分钟;**rejected/超时绝不假 tx_hash** → STOPPED。
- `HUMAN_GATE` 接真 `interrupt` + `checkpointer`(回放的脊椎顺手接上)+ `run_tracer` resume 循环;`HERMES_GATE=stub|real` 第三个接缝开关。

### 实跑:conflict 路完整闭环(真人闸 money shot 已发生)

提交 12:54:34 → 手机弹批 → **12:54:58 我亲手批了这一笔** → 真 tx `0x4832…` Success。reject 路手机全程不响(提交前就被拦)。allow 路当次 exit=4 是因为 pact 当时还没批(12:54:16 才 active)——铁律守住,干净 BLOCKED 没假 tx,重跑即通。

### 最大的认知:额度耗尽撞出一个论点级 bug

跑完发现今天 gpt-5.5 网关额度早用完了(`429 DAILY_LIMIT_EXCEEDED`)——可表头写着 `brain = gpt-5.5`,跑得还很顺。因为失败回退 stub 是**静默**的:判断全是 stub 做的,输出里零提示。一个主打可审计的 Agent,自己的证据没记录"判断是谁做的"——这不是小瑕疵,是论点级缺口。当晚修掉:PLAN 审计日志显式报 `⚠5/6 回退 stub`,`plan_evidence` 带 brain_calls/brain_fallbacks。意外收获:现场网关抽风时屏幕会诚实显示回退,这本身就是可审计叙事的一部分。
